feat: patch-only diffs - `create_diff_patch_source(hunks, {lang, a_line_count, b_line_count, patch_context})` makes a `DiffPatchSource` from one file's `DiffHunk`s (a `git diff` patch, without either text), which the renderers draw like a `DiffModel` of the same diff: the same rows, numbers, pairing, and emphasis where it holds the rows (and the same hunk indices up to the patch's context), and a count row for the unchanged lines it lacks. The count after the last hunk is unknown unless a line count, a final `no_newline`, or `patch_context` (the patch's `-U`, which proves the end of a file whose last change is near it) says. Each run of contiguous hunks lexes as its own snippet per side, so highlighting is approximate. `hunk_ranges` trims and splits the patch's hunks for a smaller `context_lines`, and keeps them for a larger one. Malformed hunks, and counts the hunks contradict, throw. `DiffRowSource` gains `b_through(index)`, the last `b` line at or before a row, which a source lacking rows must supply (a hand-written source implements it). `CodeDiff` takes `hunks` (with `a_line_count`, `b_line_count`, and `patch_context`, contradicted ones counting as unknown) as an alternative to `a` and `b` or `source`; swapping the hunks, or a patch source passed as `source`, for the full diff upgrades the view in place: `expanded` and `highlight` carry over, and the first row in view stays put
