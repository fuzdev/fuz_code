diff_html.ts

Diff-viewer HTML generation: syntax-highlighted diffs with CSS classes, as unified rows or side-by-side cells, composed from @fuzdev/fuz_util's diff data and the lexer substrate's per-line renderer. The returned HTML is the rows only — the caller owns the wrapper element (CodeDiff.svelte renders <div class="code_diff">, with split added for the side-by-side view, styled by theme_diff.css).

The pipeline is three cacheable stages. A DiffSide is one lexed text, reusable across any number of diffs (a consumer caches it by content). A DiffModel is two sides plus their DiffLines, computed by diff_lines or supplied by the caller, with the pairing of changed lines and their emphasis worked out lazily, one change at a time. The renderers draw any DiffRowSource — the narrower surface a model implements — as a range of rows (render_diff_unified_rows_html, render_diff_split_rows_html) or the whole document with its unchanged regions elided (render_diff_model_unified_html, render_diff_model_split_html); render_diff_unified_html and render_diff_split_html do all three stages from two strings.

Every row carries its line numbers as data-a / data-b (absent on the side it lacks) and, inside a hunk, the hunk's index as data-hunk, so a consumer maps an element to its line by event delegation; apply_diff_highlight restyles highlighted rows in place.

A diff known only by a patch's hunks renders through create_diff_patch_source, highlighted approximately — each run of hunks lexed on its own — with the lines between hunks counted, until the texts arrive and a DiffModel replaces it.

elide: 'expand' bounds the DOM of a big diff with a way back: elided regions render as count rows with expand controls, and the lines in expanded (b line numbers) as rows. render_diff_segments renders the document in keyed pieces, so a component re-renders only the pieces an expansion changes.

Creates a DiffPatchSource from a patch's hunks — one file's, in order, as fuz_util's diff_hunks returns them or its patch parser reads them from git diff output. Each hunk's lines must number its header's lines consecutively (a side with no lines starts at the line before the hunk, as in @@ headers), hunks must be in order without overlapping, and the unchanged lines between two hunks must be as many on both sides. Throws otherwise — a bug in whatever produced the hunks, since a patch from outside is validated where it's parsed. Nothing is lexed until rows are drawn.

The line counts and patch_context are claims about the texts that the hunks can contradict — a count short of the hunks' last line, two counts leaving different numbers of lines after the last hunk, or a count past a proven end — and a contradiction throws too. CodeDiff, which may get a count meant for other hunks while new ones arrive, treats a contradicted count as unknown instead.

DiffModel
#

diff_html.ts view source

DiffModel import type {DiffModel} from '@fuzdev/fuz_code/diff_html.js';

A diff of two whole DiffSides, what the renderers draw. The model owns what depends on both sides — the hunks for a context size, which removed line pairs with which added line, and the pairs' emphasis — and computes each lazily, so rendering a few rows of a large diff pairs only the changes those rows are in.

Within a change (a run of removes and the adds after it), lines pair by similarity: among the ways to pair the change's lines without crossing, the one with the highest total similarity, so a removed line pairs with the added line it became wherever that sits. A change whose estimated pairing work is past a fixed budget pairs by position instead.

DiffPatchSource
#

diff_html.ts view source

DiffPatchSource import type {DiffPatchSource} from '@fuzdev/fuz_code/diff_html.js';

A diff known only by its hunks — a patch's, as from git diff, without either text — that the row renderers draw like a DiffModel of the same two texts: the same rows with the same numbers, pairing, and emphasis wherever it holds the rows, and a count row for each stretch of unchanged lines it doesn't. Up to the patch's own context, context_lines makes the same hunks with the same data-hunk indices; past it the patch has no more lines to show, so its hunks are smaller than the model's and may index differently. Until the line counts are known, the gutter fits the largest line number the hunks hold, so it can be a char narrower than the model's.

Its highlighting is approximate. With no whole text to lex, each run of contiguous hunks lexes as a snippet, one per side (its context and removed lines for a, its context and added lines for b), so a hunk that starts inside a construct opened in the lines before it — a block comment, a template literal — highlights as if the construct weren't open. A language with a snippet_prefix guesses the context a snippet starts in, carried from snippet to snippet of a side — the built-in Svelte, HTML, and markdown lexers find a hunk inside a <script> or <style>, or a fence — and a wrong guess mis-highlights the snippet. A snippet's damage stays in its own hunk. The cure is to fetch both texts and render a DiffModel instead, which CodeDiff swaps in without losing its place (see CodeDiff's hunks).

Renders a DiffModel (or any DiffRowSource) whole, as render_diff_model_unified_html or, with split, render_diff_model_split_html does, but in pieces whose HTML joins to that render: each hunk, each elided region, and with elide: 'expand' each run of revealed rows and each count row between them.

A component renders each segment with its own keyed {@html}, so an expansion replaces the segments it changes and leaves the rest of the DOM alone; the split view's segments are cells of one flat grid, its count rows spanning both columns. Pass the last render's segments as previous — of the same source with the same options apart from expanded — and segments with the same key are reused rather than rendered, and runs of revealed rows keep their old bounds as cuts, so revealing lines next to a run renders only those lines as a new segment.

A count row with expand controls is <div class="diff_skip diff_expand" data-b-start data-b-end> naming the hidden b lines, holding a <button data-expand> per DiffExpandDirection it offers, labeled for assistive tech; diff_expand_range says what a control reveals. Lines of an elided region the source holds no rows for render as a count row with no controls in every mode but 'omit', which counts the whole region in one row.

diff_html.ts view source

(model: DiffRowSource, start: number, end: number, options?: RenderDiffRowsOptions): string import {render_diff_unified_rows_html} from '@fuzdev/fuz_code/diff_html.js';

Renders rows start up to end (indices into model.lines) as unified-diff rows: one element per line — <ins>/<del> for added/removed lines (semantics survive copy/paste and screen readers), <span> for context — carrying diff_line plus diff_add/diff_remove/diff_same, diff_highlight when highlight matches, data-a/data-b line numbers, and data-hunk inside a hunk. Gutters are aria-hidden and unselectable, and the +/- markers are CSS generated content, so selecting and copying yields clean code (an empty line carries a <br> so the copy keeps it). Removed rows render from a's highlight, added and context rows from b's. No elision: the caller decides which ranges to show, and how to show the rest. The range is clamped to model.lines.
