lexer.ts

Flat-event lexer substrate — the engine beneath the per-language lexers (lexer_json.ts, lexer_ts.ts, …).

Tokens are emitted as variable-length records into one Int32Array:

  • leaf: [type_id, start, end] where type_id > 0
  • open: [-type_id, start] — opens a container token
  • close: [0, end] — closes the innermost open container

Untyped text is implicit — it's the gap between events, recovered from offsets. Adjacent same-type leaves are coalesced at emit time so runs like }); become one span.

lex_syntax(text: string, lang: SyntaxLang, langs?: Map<string, SyntaxLang>, types?: TokenTypeRegistry): LexedSyntax

Lexes text with lang, returning the flat event stream.

The result is valid until the next lex_syntax call: every call writes its events into one reused buffer, which is also why events runs past events_len. Use the result right away, or keep a copy with copy_lexed_syntax. A buffer allocated per call would be off-heap memory, zero-filled up front and freed only at a later GC, which on small inputs costs more than the lexing.

import {lex_syntax} from '@fuzdev/fuz_code/lexer.js';

One instance alive for the class's lifetime. V8 holds the hidden class of an initialized Lexer only through live instances, and lex_syntax makes one per call, so without it a major GC between calls clears the class and discards every optimized lexer function that embeds it. What advance_probe returns when the text has no further occurrence: past the end of any string, since V8 caps string length below it. It is a small integer rather than Infinity so probe-cache fields, which start at -1, never change representation: a double stored there gives the cache a hidden class that only live caches hold, so a major GC between lex calls would discard every optimized lexer function that embeds it.

render_syntax_html
#

lexer.ts view source

render_syntax_html(lexed: LexedSyntax): string

Renders a lexed event stream to HTML in one forward pass. Gap text is copy-escaped; token spans use the precomputed open tags.

The result is built by appending, which in V8 makes a rope the first read copies into one string, at a cost per piece. So the loop appends few pieces and flat ones: an open tag is a single string rather than the tree + would have left at intern time, which every span would otherwise carry into the rope, and a one-char leaf, the most common kind in code, appends its whole span from TokenTypeInfo.char_spans. Text is sliced without a scan while the next character needing an escape, tracked by monotonic probes, lies past it.

import {render_syntax_html} from '@fuzdev/fuz_code/lexer.js';

render_syntax_html_lines(lexed: LexedSyntax, options?: RenderSyntaxHtmlLinesOptions): string[]

Renders a lexed event stream to one HTML fragment per source line — the same single forward pass as render_syntax_html, but token spans left open at a newline are closed there and reopened on the next line (splitting leaves that span newlines), so every fragment is balanced HTML. Fragment i is line i + 1 (1-based); newlines are not included, and a text ending in \n yields one final empty fragment. Optional marks wrap text ranges with mark tags.

lex_to_brace
?: (lexer: Lexer, stop_word?: string) => number
#

Lexes from lexer.pos as lex does, but stops at the first } that closes no { of the region's own, for a host whose region ends at that brace (a Svelte {expression}). Returns the brace's index, leaving lexer.pos there, or -1 after lexing to lexer.end without meeting one. The lexer finds the brace as it tokenizes, so a brace in a string, comment, or regex doesn't count. Optional: a host falls back to finding the brace itself.

With a stop_word, it also stops before that word where it stands alone outside every bracket of the region (the as of a Svelte {#each}), and returns the word's index instead; the host tells the two apart by the char there.

snippet_prefix
?: (lines: readonly string[], state: unknown) => SyntaxSnippetPrefix
#

Guesses what came before a snippet cut from a larger text — a diff hunk's lines without the rest of the file — so it lexes in the context it had there: the returned prefix (an opening <script> for a hunk inside one, say) is lexed before the snippet's lines and left out of the output. Consecutive snippets of one text call it in order, each given the state the previous call returned (null for the first), so a boundary one snippet shows carries to the next. Optional: without it a snippet lexes as a whole document. A guess, not a parse — a wrong prefix mis-highlights lines a plain lex would have right, so it should guess only where the snippet's lines say enough.

WordIndex
#

lexer.ts view source

A fixed table of ASCII words, each carrying an integer, that a span of text is looked up in without slicing it out. A lexer classifying every identifier through map.get(text.slice(start, end)) allocates and hashes a string per identifier; find compares char codes against the few words of the span's length and first char and returns the matching word's integer, so the lexer branches on a number. The integer is the lexer's to define: a kind, or a kind with flag bits beside it.
